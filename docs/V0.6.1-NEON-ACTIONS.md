## Egyszeri titokbeállítás (a felhasználó végzi)

1. A Neon konzolban válaszd a fenti projektet, `preview` branchet és `jg_os_preview` adatbázist.
2. A **direkt, nem pooler** PostgreSQL kapcsolati URL-t másold ki a `jg_os_preview_owner` szerepkörrel; legyen benne `sslmode=require`.
3. A privát GitHub repositoryban: **Settings → Secrets and variables → Actions → New repository secret**.
4. A secret neve pontosan `JG_NEON_PREVIEW_DATABASE_URL`; értéke a Neon kapcsolati URL. Soha ne másold be a chatbe, issue-ba, PR-ba vagy commitba.
5. A secretet ne tedd `NEXT_PUBLIC_*` változóba, és ne állítsd be productionhoz. Ne tegyél másik környezetből származó URL-t ide.

A repository privát és az aktuális GitHub csomagban a védett environment secret/approval szabályok elérhetősége eltérhet. Ezért a workflow repository secretet használ, **de kizárólag manuális indítást, fix célpontellenőrzést, rögzített forrás-SHA-t és pontos megerősítést** enged. A repository secretet módosítani tudó adminok és a workflow-t módosítani/indítani tudó személyek hozzáféréseit külön kell kezelni. A repository secrets nem jelentenek teljes elkülönítést a megbízhatatlan workflow-kódtól.

## Aktiválás és első futtatás

1. Review-zd a `chore/jg-os-preview-migration-workflow-v061` branch kizárólag két fájlját; a workflow aktiválásához **külön engedéllyel** merge-eld a PR-t az alapértelmezett ágba (nincs production deploy).
2. GitHub → **Actions → JG OS - Neon preview database migration → Run workflow**. Válaszd a **default branchet**, `operation=status`, `confirmation` üres. Várható: `Séma állapota: schema_missing`, nem hiba.
3. Az első migrációhoz ugyanott `operation=migrate` és `confirmation=MIGRATE JG PREVIEW`. A workflow a review-zott commitot checkoutolja, `npm ci`-t és a meglévő `npm run db -- migrate` parancsot futtatja.
4. A migráció után külön `operation=status` indítás ellenőrzi a `0001_init` sémát (várható: `Séma rendben (0001_init)`).
5. Az első migrációt követően Neon MCP-vel, csak olvasással ellenőrizd: `meta.environment=preview`, `schema_migrations`, `jg_app` jogosultságai, RLS és a customers/tasks/users táblák rekordszáma 0. **Semmilyen tesztügyfelet nem szabad seedelni**.
6. Ha a migráció sikertelen, ne indíts automatikus ismétlést; olvasd el a hibát, titkok nélkül dokumentáld, és javítás előtt egyeztess.

A workflow rögzített forrás-SHA-ja megakadályozza, hogy kézi inputból tetszőleges kódot futtassunk DB-jelszóval. Új adatmodell esetén a forrás-SHA-t csak egy új, külön review-zott PR-ben módosítsuk. Production célpontra nem bővíthető e workflow: ott külön folyamat és kifejezett jóváhagyás kell.

## Futtatási biztonság

- Minimum jogosultság: `contents: read`; `concurrency` párhuzamos migrációt akadályoz.
- Futtatási határidő 15 perc; nincs polling-loop, nincs E2E-ciklus.
- `migrate` csak pontos megerősítéssel; más esetben megáll az írás előtt.
- Fix host, database, user és TLS-ellenőrzés; a v0.6 `JG_ENV=preview` címkézése megakadályozza a környezetkeverést.
- A workflow a DB titkát nem írja ki; kód, napló, artefaktum nem tartalmazhatja.
- A workflow futása során **csak egyszer** végezze el a migrációt. Ismételt `migrate` külön jóváhagyás után lehetséges és a migráció idempotens.

## Korlátok

A workflow még nem ellenőrzi az alkalmazás teljes üzemkészségét, a Vercel integrációt, a szolgáltatói backupot és a Trello-importot. Nincs éles ügyféladat-kezelési jogosultság. Az újonnan készülő CRM-funkciókat továbbra is külön preview/QA és compliance-review előzi meg.

Ha az első migráció `permission denied` vagy Neon-szintű role/RLS inkompatibilitási hibával áll meg, **ne** kapcsold ki az RLS-t, és ne kerüld meg a meglévő v0.6 szabályokat: készíts célzott vizsgálatot és új, review-zott javító PR-t.
