# v0.9 — Feladatlezárás, átidőzítés, Előzmények, globális kereső

2026-10-19. Kiindulás: v0.8 (`9fdc136`, `feat/jg-crm-google-production-v08`). A kód és a tesztek elkészültek; **éles migráció és éles telepítés nem történt**, mindkettő külön jóváhagyásra vár.

Csak a bejelentkezés után betöltött snapshotban keres. A Pipeline saját keresőmezője megszűnt. |

## Adatmodell

- Új migráció: `0003_task_outcome` — `task_results.outcome text NULL` (`'success'` / `'failure'`), plusz két CHECK: érvényes érték; minősített sornál az `output_text` nem üres. Kizárólag additív.
- A minősítés (`outcome`) és a szöveg (`output_text`) külön oszlop. A régi `output_key` (v0.6–v0.8 legördülő) és a régi szöveg változatlan; a régi sorok `outcome` értéke NULL marad (nincs kitalált minősítés).
- Napló: a meglévő `activities` tábla. Lezárás: `task_completed`, `meta.taskOutcome` + `meta.output` (az adott lezárás szövege). Újranyitás: `task_updated`, `meta.taskChange = "reopened"`. Átidőzítés: `task_updated`, `meta.taskChange = "rescheduled"`, `fromDueAt`, `toDueAt`. A korábbi naplóbejegyzések nem módosulnak.
- Audit (`audit_events`): `task.close` → `{ outcome, outputLength }` (a szöveg nem kerül az auditba).
- API: `task.close` → `{ taskId, input: { outcome, output } }`. A régi `{ outputKey, outputNote }` alak 400-at kap.
- Mentés/visszaállítás: a v0.8-as (`0002_google_auth`) mentés a v0.9 sémába visszaállítható (az új oszlop NULL). A v0.9-es mentés a v0.8 alkalmazás `restore` parancsával nem tölthető vissza (eltérő sémaverzió).

## Éles bevezetés (JÓVÁHAGYÁSRA VÁR — nem futott)

Sorrend számít: a v0.9 alkalmazás `schema_outdated` (503) állapotot ad, amíg a 0003 nincs alkalmazva; a v0.8 alkalmazás viszont a 0003-as sémán is változatlanul fut.

1. Kézi Neon snapshot az éles adatbázisról (azonosító rögzítése), illetve logikai mentés: `npm run db -- backup <fájl>` a tulajdonosi kapcsolattal, titkosított helyre.
2. Preview-n előbb: a meglévő, kézzel indítható `jg-neon-preview-migration` workflow-val, fiktív adaton; v0.9 preview telepítés és kézi ellenőrzés.
3. Éles migráció a tulajdonosi kapcsolattal: `npm run db -- migrate`, majd `npm run db -- status` → „Séma rendben (0003_task_outcome)”. A v0.8 közben fut tovább.
4. v0.9 commit telepítése productionre.
5. Füstteszt fiktív ügyfélen: lezárás mindkét gombbal, újranyitás, átidőzítés, Előzmények, kereső; régi (v0.8) lezárt feladat olvasható.

## Visszaállítás

- Alkalmazás: a v0.8 deployment visszaállítása (Vercel „Instant Rollback” / újratelepítés). A 0003-as séma mellett a v0.8 működik; a v0.9 alatt rögzített lezárások szövege v0.8-ban is látszik, a minősítés ott nem jelenik meg (az adat megmarad).
- Séma: visszabontás nem szükséges és nem javasolt. Ha mégis kell, az `alter table task_results drop column outcome` destruktív (a minősítések elvesznek): csak külön jóváhagyással, `-- allow-destructive:` jelöléssel és `JG_ALLOW_DESTRUCTIVE_MIGRATION` engedéllyel, előtte snapshottal.
- Adat: Neon snapshot / point-in-time visszaállítás (6 órás ablak), vagy a logikai mentés üres adatbázisba.
